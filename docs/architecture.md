# Architecture

This document is the design for `dsh-raw-agent`. It says what we build, why, and how we prove it.

- **Versions it was designed against:** DSH 0.2.2-rc.1, Claude Code CLI 2.1.318, Claude Agent SDK 0.3.318, Node 24, pnpm 11.
- **Inputs:** the raw contract in [CLAUDE.md](../CLAUDE.md), the requirements in [requirements.md](requirements.md), and the Phase 1 research notes in [research/](research/). Each decision links to its evidence. Evidence uses aliases: `P/<dsh package>/lib/…:N` (an installed DSH 0.2.2-rc.1 package), `SDK/sdk.d.ts:N` and `SDK/sdk.mjs` (Agent SDK 0.3.318), `CLI 2.1.318 binary` (a string search of the binary), and "Phase 1 recording `<name>`" (an SDK wire recording kept in the local research folder).
- **How this design was made:** the three Phase 2 architecture proposals were not produced, so the judges scored nothing. This design is built directly on the Phase 1 notes, the judges' fact baselines and rubrics, and the lead's defaults.
- **Revision 2.** Two rounds of adversarial review found log-corruption paths, raw-contract gaps and missing CLI behaviours. This revision fixes them. New or changed decisions are marked **(r2)**. Points we did not accept, or accepted only in part, are in §13 with a reason.
- **Revision 3.** A third review round found a second DSH stream check the writer did not meet, a rule-3 path through DSH-injected notices, a job controller missing in the web profile, DSH internals spread outside one adapter, and a core interface shaped around Claude's session model. This revision fixes them. New or changed decisions are marked **(r3)**. Rejected or partly accepted points are in §13.
- **Revision 4.** A fourth review round found that a profile-installed plugin cannot write an ignorable `plugin:` record (so D82's binding record would make a log unloadable), no log-safe path for a whole (non-streamed) main-thread response or the CLI's `tombstone` frames, a plugin config edit that remounts the Host entry and ends every live CLI, and pre-spawn capabilities placed on an object that exists only after a spawn. This revision fixes them and several smaller points. New or changed decisions are marked **(r4)**. Rejected or partly accepted points are in §13. Points that only a live run can settle are go/no-go checks in §11.
- **Review status.** In each of the four review rounds, all three reviewers still found at least one major point, but the points moved from core design flaws to edge cases (reviewer scores rose from about 60 to about 75). Further paper review has low value, so the lead moved to the Phase 3 spike: the remaining risks are settled there by live go/no-go checks (§11), and any spike failure reopens the design.
- **Marking:** **unverified** means inferred from code or docs and not yet run. Every unverified item that matters has a Phase 3 spike (§11).

## 1. The design in one page

1. **Seam.** An agent preset mounts an agent-scoped `agent/pre-step` **driver**. The driver runs each turn in the user's own `claude`, writes the transcript as native DSH events, and returns `{kind:'enter', messages: []}`, so DSH never calls a model. A second agent-scoped listener, registered with `prepend: true`, forces `messages: []` after every other listener.
2. **One process per session, started only when the user asks.** One long-lived SDK `query()` in streaming-input mode. It starts on the user's first message, or when the user presses "Start Claude Code" on a control that needs a live process. Never on session open, never as a probe. Stop calls `interrupt()` only. The process ends only on dispose or "Force stop".
3. **Raw start options.** The user's binary, the `claude_code` preset with no append, all three setting sources, the user's env minus a verified host-variable list (with `NODE_OPTIONS` and `DEBUG` put back), and no `model`, `effort`, `permissionMode`, `tools`, `settings` or `thinking`. Two TUI defaults that SDK mode turns off are turned back on (question previews, file checkpoints).
4. **Native events, written in a safe order.** One DSH step per main-thread Claude API call. `assistant/message` is written at `message_stop`, then each `tool/call`, then the **buffered** `tool/result`s, then `step/end`. The writer itself refuses any event that would break a v4 rule, and **(r3)** any `assistant/message` whose embedded stream does not reproduce its content, usage and replay state.
5. **Turns follow the CLI's input.** The plugin tracks every **human** message it sends to the CLI **(r3)**. A DSH turn ends only when the CLI has consumed all of them. Any CLI turn that starts while no DSH turn is open becomes a wake turn.
6. **Agents.** Every Claude subagent, workflow agent and teammate becomes a one-shot DSH **child session**. A child is written by a mirror-only listener that never starts a process and never sends anything. Background tasks become DSH **jobs** served by our preset's own scoped job controller **(r3)**.
7. **Interaction.** One plugin interaction channel carries permissions, plan approval, questions with previews, MCP elicitations and the workspace-trust question, inside or outside a turn. Reject texts are the CLI's own constants, as the TUI sends them.
8. **Backend interface.** All Claude code sits behind `AgentBackend` in its own packages. The DSH layer imports only the backend-neutral core. **(r3)** The DSH layer gets a list of backend factories, mounts one preset and one catalog provider per factory, and reads id choice, resume and fork support as capabilities. **(r4)** Every capability the DSH layer needs before a process exists is on the factory, not on the session. All DSH touch points sit in one `dsh-port` module per side. A stub backend with agent-chosen ids and no fork runs the DSH-layer tests beside Claude.
9. **Services.** A Host service `rawAgent` and a Client service `rawAgentClient`. Other plugins can read state, interrupt, and **prefill** our composer. Sending text to the model directly needs a per-plugin grant the user creates.

## 7. Backend interface

### 7.1 Rules

- `packages/core` defines the interface and the event union. It imports nothing from DSH and nothing from any agent SDK.
- `packages/backend-claude` implements it and is the only package that imports `@anthropic-ai/claude-agent-sdk`.
- `packages/dsh-host` and `packages/dsh-client` import `core` only (and `import type` from DSH packages). Claude tool views live in `packages/views-claude`, a client package keyed by backend kind; `dsh-client` loads view packs by `backend.kind` and never imports one by name.
- Backend-specific lists (permission modes, plan choices, reject behaviour) are **data** from the backend, not code in the DSH layer.
- Optional features are `undefined` when a backend (or the user's CLI version) lacks them. The UI hides what is missing, or offers "Start <displayName>" when `capabilities.needsProcess` lists it. **(r4)** Before a spawn the DSH layer reads only `factory.staticCapabilities`; after the spawn it reads the session's `capabilities`, which may only remove or narrow entries.
- **(r3)** The DSH layer never assumes Claude's session model: id choice, resume and fork are capabilities (D82), and no-process reads are factory methods (D83). `plugin/` is the composition root that passes the factory list (D80).
- **(r3)** Interactions reach the DSH layer through `InteractionHandler` calls, not the event stream; `interaction-done` and `interaction-cancel` are events. §6 writes them as `interaction {…}` for brevity.

```ts

export interface RawAgentService {
  readonly apiVersion: 1;
  readonly backends: readonly { kind: string; displayName: string; version?: string }[];
  sessionInfo(sessionId: string): Promise<RawAgentSessionInfo | undefined>; // never spawns

  onEvent(sessionId: string, listener: (e: RawAgentPublicEvent) => void): () => void; // data not in the native log only
  /** Direct paths: refused unless `grant` is a token the user created for this plugin (D66). */
  send(sessionId: string, text: string, grant: string): Promise<{ messageId: string }>;
  steer(sessionId: string, text: string, grant: string): Promise<{ messageId: string }>;
  askSideQuestion(sessionId: string, question: string, grant: string): Promise<string | null>; // writes nothing to any log
}
export interface RawAgentClientService extends RawAgentService {
  /** Put text in our composer (or the /btw box). Nothing is sent until the user presses Enter. */
  prefill(sessionId: string, text: string, target?: 'composer' | 'side-question'): Promise<boolean>;
}
// RawAgentPublicEvent: state | usage | workflows | children | asks (id, kind, agent, title, at only) | ended
```

- Other plugins read the native DSH log first (rule 8). `onEvent` carries only data the log does not have (process state, usage and cost, workflow snapshots, child agents, which asks wait, without their choices or answers). One pure `PublicEventTracker` (core) builds the events on both halves.
- Default: only `prefill` can put text toward the model, and the user sends it. A granted `send`/`steer` message carries **(r4)** `source.kind: 'raw-agent-plugin'` plus `grant: '<grant label>'` and `grantId` in `source` (never `'user'`, which DSH reads as typed by the human, D66), so the log shows who sent it. Grants are listed and revocable in our config panel (DSH settings section "Agent plugin access", and our settings dialog).
- **(M8)** The Host service admits each granted message id in the Host registry before it calls DSH's `followup`/`steer`; the agent mount forwards a `raw-agent-plugin` message only when it was admitted (D22, D27), so a plugin that calls `agent.followup` itself is dropped like a DSH notice. The admission is in memory: a granted message still queued at a DSH restart is dropped (known gap).
- **(M8)** Grant storage: only the token's SHA-256 hash, in the Host entry config field `grants`, written with Cordis `ctx.fiber.update`. The entry's own `internal/update` hook takes a change of runtime fields only (`grants`, `executablePath`, `options`) in place without `next()`, so no remount ends a CLI (D87). **Live (M8, S7):** a user's edit of these fields in the profile patch also goes through this hook (same CLI pid after each edit; the bypass option turned off at once). But the loader does not save our own write for a row a bundle layer inserted (DSH 0.2.2-rc.1 changes the composed tree only), so grants stored there last for one DSH run. **(D88)** Grants now live in a DSH storage domain (`ctx.storageDomain`) and survive a DSH restart; the panel says "saved: kept after a DSH restart". The entry config is the fallback when that store is missing (the panel then says "kept until DSH restarts").
- `askSideQuestion` never starts a process (`not-running` refusal, rule 9); the exchange also shows in our `/btw` panel.
- The Client service calls POST routes under `api/raw-agent/plugin/…` and `api/raw-agent/grants…` (D62); a refusal answers `{error, code}` and never 401.
- Approvals and answers are never exposed.

## 10. Test strategy

### 10.1 Unit tests (fast, no processes)

- **Env policy** (D17a, D7): every listed name removed, conditional rules, Windows case-insensitivity, user tokens kept, `NODE_OPTIONS` and `DEBUG` restored, the DSH process's `CLAUDE_AGENT_SDK_VERSION` unchanged after `query()`.
- **Binary resolution** (D10) per OS, with a fake file system.
- **Start options** (D12–D16, D73): a snapshot of the exact SDK options object, including the `previewFormat` env rule, the checkpoint rule (**(r3)** each source: three settings files, managed settings, `~/.claude.json`), the bypass switch (settings alone do not add it), and `workspaceTrust` only after acceptance.
- **Ids** (D5): derived ids are stable and valid UUIDs; fork and reset change them as specified.
- **Reject mirror** (D40, D42): each case (main/subagent, with/without feedback) gives the CLI constant and `interrupt` as listed.
- **Model-choice rules** (D35): own and inherited `model/selection`, other providers, `settings`, reset without a user effort value, fork before and after a choice, pending choices before spawn.
- **Sent-input tracking** (D27): steer consumed in-step, consumed in a later CLI turn, cancelled on Stop, never forwarded twice. **(r3)** Only `source.kind === 'user'` (or a granted origin) is sent at `inserted`; consumption on `command_lifecycle started` or a uuid in any frame's `user_message_uuids`, never waiting for `completed`; the no-signal fallback ends the turn on `queued_turn_count` 0/absent; cancelled ids (interrupt response and `cancelled` lifecycle) leave the map.
- **(r3) Stream encoder** (D17 f): for every block shape (text, reasoning with signature, tool call with empty input), the encoded stream replayed through the real `BlockAssembler` gives the exact content, usage and replay state; the finish reason rule; the interrupt cases (started tools, text prefix only, nothing visible).
- **(r4) Inbox and grants:** a queued follow-up runs as turn 2 (D3 splice-out, then `send`); a steer cancelled on Stop is removed from `nextStep` and not sent at the next claim (D25); a granted message has `source.kind: 'raw-agent-plugin'` and is never cited by a title (D66, D32); a dropped `schedule` reminder shows the note (D22); the 11th background task gets a plugin row when `ctx.jobs.start` hits the per-owner limit (D47).
- **(r4) Config:** each runtime-editable Host config field is volatile in the schema (D87).
- **(r3) Fork hint** (D29): `resumeDropsTurn` is passed for exactly one dropped user turn, and not for two turns, a merged steer turn or a wake turn.
- **Usage math** (D57–D60): de-duplication by `message.id`, cumulative deltas, re-base on reset, synthetic steps skipped, resume baselines, `costBasis` labels.
- **Workflow snapshot merge** (D48), **job waits** (D47): no moment without a waiter across a task longer than one wait; teardown settles locally without `stopTask`.

### 10.2 Mapper and writer tests (recorded wire, real DSH checker)

- Fixtures are SDK wire recordings from the Phase 1 probes, scrubbed of ids and paths: text; one tool (`probe1 bash`); parallel interleaved tools (`probe6 Q`); thinking with empty text and a signature; interrupt mid-tool; steer during a tool and during final text; background completion with a self-started turn; `num_turns: 0`; local commands; `/clear` with `conversation_reset`; API errors (`authentication_failed`, `rate_limit`, `prompt_too_long`); error result subtypes; `tool_deferred`; a failed attempt followed by a retry; a re-sent assistant message; subagent; workflow with transcript files; teammates; plan approval; elicitation; CLI death with open child steps.
- **(r4)** Added fixtures (hand-built until S1 records the real shape): a partial stream, then a whole fallback response with a tool call; a stale open step followed by a whole response; `tombstone` frames for an abandoned attempt's assistant message and tool result (buffered and already written); a tool result with an image (D85); a `redacted_thinking` block (D86).
- **(r3)** Added fixtures: the `probe2B` steer fold (uuid first on `status.user_message_uuids`); an interrupt after a tool started; an interrupt during text only; an interrupt before any visible output; an in-turn permission ask (approval audit pair, D44).
- Each fixture runs through `backend-claude` → `dsh-host` writer inside the in-process DSH loop harness. The resulting root and child logs must pass the live append, the real v4 relationship check and a JSONL reload, **(r3)** and the stream replay check: every `assistant/message` and `assistant/attempt` stream is expanded with `expandAssistantStream` and replayed through the real `BlockAssembler`, and `content` (or the interrupted prefix), `usage` and `replayState` must deep-equal the result, exactly as DSH's generation check does. The export must contain the tool calls.
- **Negative tests** keep each rule honest: the writer refuses a `tool/call` without its advertised block, a `tool/result` before its `tool/call`, any `request/context`, a `turn/end` with an open step, and any root or child event outside an open turn. **(r3)** It also refuses an `assistant/message` whose usage has no matching `usage` chunk, whose `replayState` differs from `finish.replayState`, that is `interrupted: true` while keeping a tool call, or that keeps a tool call under a `max-tokens` finish; and the harness's stream check catches each of these when the writer's assert is switched off. **(r4)** It also refuses a non-user `session/title` that cites a non-human or later message, an `agent/inbox/spliced` with an out-of-range `start`/`removedCount` or a duplicate id, and any `plugin:` type; and a test shows that a `session.append('plugin:…')` event written past the assert is refused on reload.

### 10.5 Live acceptance suite
